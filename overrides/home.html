Orchestration that starts as one local file.

Cereyan is a minimal, local-first orchestrator for Python data pipelines. A Rust core sits behind a thin layer of decorators, and the whole thing ships as one wheel with no runtime dependencies.

Three ways to run the same file.

No daemon to register with, no manifest to publish. The script is the pipeline.

$ python pipeline.py
records a run in ~/.cereyan/db.sqlite
$ cereyan run pipeline.py:etl --param day=2026-01-02
the same, with parameters and a summary
$ cereyan serve .
API, UI, scheduler and engines on 127.0.0.1:4200

One process serves the whole thing.

The API, the web UI, the scheduler, a warm pool of engine processes, rules, and a built-in MCP server for agents, all behind a single cereyan serve.

Offline first

A script records runs into a local SQLite file. Nothing else needs to be running, and nothing leaves the machine.

One process to serve

API, UI, scheduler, engine pool, rules and MCP in one command. One wheel, with no runtime dependencies to resolve.

Pipeline semantics

Targets, backfills, keyed resources, chaining and fan-in, unique keys, and rules that react to events or to their absence.

Durable runs

Every finished task is checkpointed, so a retry resumes after the last one. A run can sleep or wait without holding an engine.

Built for the things data pipelines actually do.

Targets

Reruns only do the missing work.

Declare where a task writes. When that output already exists the task ends Skipped and the body never runs, so rerunning a day, a failed run or an entire backfill is safe.

Idempotent reruns 
@task(output=lambda day: LocalTarget(f"data/{day}.csv"))
def export(day: date) -> None:
    with LocalTarget(f"data/{day}.csv").open("w") as fh:
        fh.write(rows)

Events and rules

React to what happened, and to what did not.

Every transition is an event on a live feed. Rules match them and act, and a rule can also fire when an expected event never arrives, which is how a missed delivery becomes a page rather than silence.

Backfills

Cover a date range in one command.

A backfill creates a run per date or per listed value, respects the flow's resources, and pairs with targets so a second pass touches only the days that are still missing.

Backfill a date range

cereyan backfill daily --from 2026-01-01 --to 2026-01-28 28 runs

Targets the benchmarks enforce.

Agents read the same store you do.

A built-in MCP server exposes runs, logs, states and actions as tools, so an assistant can diagnose a failure without a scraping layer. The whole site is published as one file for retrieval too.
